# G3AK — 저장된 모의 전략 비교 보고서

## 상태와 범위

**독립 리뷰 완료·원격 CI 검증 대기.** [G3AJ 자동 비교](g3aj-automatic-paper-promotion.md)의 최신 비교 요청과 결정을 읽는 API, Flutter 연결 화면을 추가한다. schema v27/backup v21과 비교·선택·실행 권한의 기존 기록을 그대로 사용한다.

실제 RED는 head `774bf923a9be641d1f3f78ed5b9e9c99bd80d476`, [Core40657897797 job122713314657](https://github.com/YouSangSon/Omni-Folio/actions/runs/40657897797/job/122713314657)에서 새 경로가 HTTP404를 반환한 실패다. 이 실패를 구현 검증 통과로 세지 않는다.

## 사용자 흐름

앱의 **연결 → 모의 전략 비교 보기**에서 가장 최근 비교 요청 한 건을 확인한다. 화면은 최종 결정, 비교 당시 후보와 선택 전략, 같은 종목의 매수 후 보유 모델을 보여준다. 세 구간의 비용 차감 수익률·최대 낙폭·완료 왕복 거래·거래 회전율을 펼쳐 볼 수 있다. 각 구간은 같은 현금으로 따로 시작하므로 구간 결과를 더하거나 이어 붙이지 않는다.

```sh
curl -fsS http://127.0.0.1:8080/v1/paper/promotion-report
```

처음 열 때와 수동 새로고침에만 조회한다. 갱신 실패 시 이전 결과와 원래 관측 시각을 함께 유지하며, 첫 실패에는 재시도를 제공한다. 빈 기록, 처리 중 표시, 오류, 작은 화면·확대 글자·키보드·화면 읽기·동작 줄이기를 지원한다. 자동매매 실행 권한이 없다는 안내는 모든 상태에서 보인다.

## 결정과 현재 선택을 구분하는 계약

비교 결과는 성적표이고, 선택 이벤트는 그 결과를 실제 선택에 반영한 기록이다. 이후 다른 전략을 고르거나 rollback하면 성적표는 그대로지만 현재 선택 기록은 달라진다. 후보의 내용이 같아도 같은 이벤트라고 간주할 수 없다.

| 최종 결정 | 공개하는 내용 |
| --- | --- |
| `PENDING` | 요청은 저장됐지만 결정 기록이 없다. 이전 성공을 대신 보여주거나 프로세스가 실행 중이라고 추정하지 않는다. |
| `PROMOTE` | 비교 기준을 통과하고 선택에 반영됐다. 정확히 그 선택 이벤트가 현재 이벤트일 때만 `current`, 그 외에는 `superseded`다. |
| `HOLD` | 비교 기준을 통과하지 못해 후보를 선택하지 않았다. 과거 판단이며 현재 안전을 뜻하지 않는다. |
| `STALE` | 적용 전 상태 검증을 통과하지 못했다. 비교 지표의 판정은 별도로 보존한다. 포괄적인 이유 코드로 계좌 변경 등 특정 원인을 단정하지 않는다. |
| `ERROR` / `ABORTED` | 결정 기록은 있지만 공개할 완료 비교가 없다. 내부 오류는 노출하지 않는다. |

적용 확인: 자동 선택 후 rollback하고 같은 후보를 수동으로 다시 선택해도 과거 자동 선택은 `superseded`로 남아야 한다. 후보 내용만 비교해 `current`로 표시하면 역사적 결정과 현재 선택을 혼동한 것이다.

## 읽기·검증·공개 경계

[GET 계약](../contracts/openapi.json)은 `paper-promotion-report.v1`의 닫힌 응답이다. 기존 `paper-monitor.v1`과 연구 보고서는 그대로 유지한다. query는 HTTP400, 지원하지 않는 쓰기 method는 HTTP405이며, 조회 응답은 `Cache-Control: no-store`다. 기존 HEAD/CORS 동작을 유지한다.

[서버](../services/core/paper_promotion_report.go)는 하나의 읽기 transaction 안에서 schema와 전체 registry 복구를 검증하고 마지막 claim, 결정, 전략을 읽는다. 복구 과정에서 저장 입력의 완료 비교를 다시 계산하므로 자기 hash만 맞춘 지표 위조도 실패한다. 과거 기록 하나라도 손상되면 부분 결과나 이전 성공으로 대체하지 않고 일반 HTTP500 오류를 반환한다. 읽기 때문에 현재 실행 권한 검증이나 새 평가·결정·선택을 시작하지 않는다.

계좌·세션·요청·선택 ID, hash, 원본 CSV·경로, 현금과 비용 금액, 내부 진단은 공개하지 않는다. 네 지표만 원래의 정확한 문자열로 투영한다. 최대 128글자, 정규 십진수, 정수 거래 횟수와 알려진 거래 횟수 정의를 검사한다. 수익률의 -100% 하한이나 낙폭·회전율의 100% 상한을 임의로 만들지 않는다. 클라이언트는 금액 환산·재평가를 하지 않는다.

완료 비교가 있을 때만 `metrics_verification=recomputed_from_stored_input`을 보낸다. 기록 시각은 UTC RFC3339Nano로 정규화한다. 비교 종료 ≤ 요청 기록 ≤ 결정 기록과 구간 순서를 보존하되, 서버 시계가 뒤로 이동할 수 있으므로 관측 시각이 과거 기록보다 뒤라는 조건은 추가하지 않는다. [Flutter 파서](../apps/client/lib/paper_promotion_report.dart)는 나노초를 잃지 않는 검증된 UTC 문자열 비교와 정확한 수량·지표 검증을 사용한다.

## 검증과 남은 범위

- 독립 리뷰에서 OpenAPI가 비교 구간의 소수 초를 허용해 Flutter와 불일치한 지적을 보완했다. 네 구간 경계는 정수 초로 제한하고 관측·요청·결정 시각의 나노초 지원은 유지하며, 수정분 재검토를 마쳤다.
- [공유 응답 8사례](../contracts/fixtures/paper-promotion-report-cases.json)를 실제 claim·비교·오류·중단·선택·rollback 흐름에서 생성한 서버 응답과 비교하고 Flutter에서도 소비한다. 최신 미결정 우선, 과거 지표 위조, 시계 역행, 읽기 전후 journal·권한·schema 불변과 비공개 오류를 검사한다.
- UI 검사는 이전 관측 보존, 결정별 문구, 정확한 지표, 320px·200% 글자, light/dark, 키보드·semantics·reduced motion과 페이지 종료 후 응답을 다룬다. 필수 공개 Ubuntu CI의 집중 검사·전체 검사·분석·web/ARM64 release 결과는 완료 후 이 문서에 남긴다.
- 로컬은 소스·JSON·상대 링크·번역 구조·gofmt 검토만 수행한다. 로컬 앱·테스트·빌드·Dart/Flutter 실행은 하지 않는다. CI에서 포맷이 실패하면 실패 job이 출력한 diff로 수정하며 실패 결과를 숨기지 않는다.

기존 SQLite `BEGIN IMMEDIATE` 읽기는 writer lock을 잡고 전체 복구는 비교 이력에 비례해 비용이 늘 수 있다. polling을 추가하지 않았으며 대량 이력에서의 지연은 측정하지 않았다. 저장 입력 재계산은 데이터 사용권·가격 조정·거래소·현재 시세·실제 지수 검증이 아니다. KRW/USD benchmark는 별도 계약을 유지한다. 실제 제공자·VM 배포·새 iOS·실기기·실주문 검증은 포함하지 않는다.
